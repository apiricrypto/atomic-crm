# اجرای عملی هسته CRM ساتنو روی ویندوز

این راهنما برای بازبینی رابط و گردش کار با داده‌های ساختگی است. نسخه تجمیعی شامل
فارسی/RTL و بخش‌های توسعه‌ای است؛ هنوز در `main` یا `satno-development` ادغام نشده.

## دریافت نسخه در پوشه‌ای جدا

Git و Node.js نسخه ۲۴ باید نصب باشند. در PowerShell، در پوشه‌ای که می‌خواهید پروژه
قرار بگیرد، این دستورها را به‌ترتیب اجرا کنید. پوشه مقصد باید جدید باشد؛ پوشه نسخه
قبلی و فایل‌های محیطی آن را تغییر ندهید.

```powershell
git clone --single-branch --branch satno/core-demo-walkthrough-20260929 https://github.com/apiricrypto/atomic-crm.git satno-crm-preview
cd satno-crm-preview
npm ci
npm run demo:satno
```

مرورگر باید روی `http://127.0.0.1:5174` باز شود. اگر خودکار باز نشد، همین آدرس را
باز کنید. پنجره PowerShell باز بماند. برای توقف `Ctrl+C` بزنید. این دستور روی
همین کامپیوتر گوش می‌دهد؛ آدرس عمومی یا دسترسی موبایل ایجاد نمی‌کند.

اگر پورت ۵۱۷۴ اشغال باشد برنامه متوقف می‌شود؛ ابتدا نسخه دموی قبلی را ببندید و
دستور را دوباره اجرا کنید. برای این دمو Docker، Supabase و فایل `.env` لازم نیست.
نصب وابستگی‌ها به اینترنت نیاز دارد. ورود نمونه خودکار است؛ رمز واقعی وارد نکنید.

## سناریوی ۱۰ دقیقه‌ای کار روزمره

با منوها بین صفحات جابه‌جا شوید؛ **Refresh/F5 نزنید**. داده‌های FakeRest در حافظه
همین صفحه‌اند و با بازخوانی دوباره ساخته می‌شوند. نام‌های انگلیسی اولیه نیز داده
نمونه‌اند و مشتریان واقعی ساتنو نیستند.

1. در «شرکتها»، یک شرکت با نام «شرکت آزمایشی خورشید اهواز» و شهر «اهواز» بسازید.
2. در «مخاطبین»، «علی آزمایشی» را ثبت کنید؛ شرکت مرحله قبل را در فیلد شرکت جست‌وجو
   و انتخاب کنید و ذخیره بزنید. ارتباط مخاطب و شرکت را در پرونده مخاطب ببینید.
3. در پرونده همان مخاطب «افزودن وظیفه» را بزنید؛ متن «پیگیری پیشنهاد سیستم خورشیدی»
   و موعد فردا ساعت ۱۰ را ثبت کنید. وظیفه باید در پرونده مخاطب نمایش داده شود.
4. در «معاملات»، «ایجاد معامله» را بزنید. نام «سیستم خورشیدی ۱۰ کیلووات — آزمایشی»،
   همان شرکت و مخاطب را انتخاب کنید. مبلغ دلخواه آزمایشی و تاریخ مورد انتظار را
   وارد کنید. عدد، قیمت پیشنهادی بازار نیست؛ واحد نمایش فرم را بررسی کنید.
5. معامله را ذخیره کنید و کارت آن را در قیف ببینید؛ پرونده معامله را باز کنید و
   ارتباط شرکت/مخاطب را بررسی کنید.
6. به «وظایف» و «داشبورد» بروید و پیگیری جدید را ببینید. سپس برای بررسی چیدمان، عرض
   پنجره را کوچک کنید یا حالت موبایل ابزار توسعه مرورگر را فعال کنید.
7. در پایان، بازخوانی صفحه را امتحان کنید: اطلاعات ساخته‌شده در این سناریو باقی
   نمی‌مانند. ذخیره در دمو با ذخیره دائمی شرکت تفاوت دارد.

## بعد از هسته CRM

بخش «مناقصات» برای بازبینی صندوق رادار، خط لوله، جست‌وجوهای ذخیره‌شده و مسیر بررسی
دستی ستاد در همین نسخه موجود است. نمونه‌های دمو اثبات اتصال به Tender Radar یا
داده رسمی ستاد نیستند. اتصال زنده، RLS، ورود واقعی و ماندگاری پایگاه داده هنوز
نیازمند آزمون جداگانه روی Supabase یک‌بارمصرف‌اند.

پس از بازبینی رابط، در همان پوشه می‌توان وضعیت پیش‌نیازهای آن آزمون را بررسی کرد:

```powershell
npm run check:tender-disposable:satno
```

موفقیت این بررسی فقط آماده‌بودن پیش‌نیازهاست و به‌معنای اجرای migration یا تأیید
پایگاه داده نیست.

## آزمون قابل تکرار برای توسعه‌دهنده

```powershell
npx playwright install chromium
npm run test:demo:satno
```

آزمون روی پورت محلی خودش اجرا می‌شود؛ دموی باز را پیش از اجرای آن متوقف کنید.
این مجموعه مستقل از آزمون‌های Supabase است و هیچ credential دریافت نمی‌کند.
